# OZON 店铺助手

**面向 OZON 多店铺卖家的经营工具：微信接收上新和出单，填采购价核算利润，再用数据罗盘查看店铺与商品表现。**

项目从10家店铺、两人共同管理的实际需求出发，将 **多店铺微信推送** 与 **采购成本、订单利润、经营榜单** 放进同一个产品。手机查看、电脑操作，无需安装专用安卓App。

## 能帮你解决什么

| 日常问题 | 产品提供的能力 |
| --- | --- |
| 多个店铺每天上新、出单，逐个后台查看费时 | 统一采集店铺动态，通过Pushplus推送到微信，多人可以共同接收 |
| 有销售额，却不知道扣除采购和各项费用后赚多少 | 同步订单售价和商品信息，填写采购价后计算包裹预估利润 |
| 核算时反复查重量、选运费公式 | 根据售价与有效计费重量自动匹配档位，并展示费用明细 |
| 采购支出散落在订单中，不方便汇总 | 采购成本统计支持日期筛选，可追溯到关联订单和商品 |
| 想知道哪些店铺、哪些商品值得继续做 | 商品与店铺双维度，查看销量榜、利润榜和亏损榜，并逐层进入订单 |

## 产品亮点

### 1. 多店铺动态，通过微信一起掌握

- **统一管理多个店铺**：接入各店铺Client ID与API Key，当前用于10家店铺。
- **上新、出单分开采集**：识别新增且确认可售的商品，订单覆盖FBS/rFBS与FBO。
- **支持共同接收**：使用Pushplus群组，将相同店铺动态发送给多位订阅人。
- **通知带商品信息**：订单推送可展示商品名、图片、售价和数量，并附利润页入口；图片或翻译未就绪时不阻塞通知。
- **按配置汇总，减少刷屏**：订单批次与上新日报分别调度；持久化事件和发送状态，正常重启不重复提醒。

采集、汇总周期以运行配置为准；API数据可见性、轮询和微信投递都会影响到达时间。

### 2. 填采购价，就能查看订单预估利润

订单卡片集中展示商品图片、名称、成交价、数量和状态。进入核算弹窗后，填写实际采购单价，即可查看采购成本、运费、平台扣费、货代费和其他成本如何影响利润。

```text
预估利润 = 核算售价 − 采购成本 − 运费 − 平台合计扣费 − 货代费 − 其他成本
```

- **自动选择计费档位**：同时判断人民币核算售价与包裹重量，无需逐单手动选公式。
- **重量来源明确**：默认采用API商品重量；实际称重不同时，可明确确认并使用自定义计费重量。
- **修改时预览**：调整采购价、重量或费用后查看试算，保存后用于后续统计。
- **费用可核对**：展示选中的档位、费率及各项费用，保留精确计算结果供核查。
- **缺资料不冒充盈利**：未填写采购成本、缺少必要售价或重量时，保持待补资料状态，不按零成本计算利润。

当前自动规则覆盖四档：售价≤135元时，＜500g为超轻小件，500g起为低客单；售价＞135元时，≤2kg为轻小件，超过2kg为大件，重量上限25kg。轻小件默认合计扣费率17%。费用规则来自当前业务核算表，**预估利润不等于平台最终结算金额**。

### 3. 采购成本看总额，也能追到每一笔

首页保留紧凑的采购成本入口，点击查看明细与日期筛选，不让详细报表挤占订单列表。

- 按“已填采购单价 × 商品数量”汇总，未填项不作为零成本。
- 同时展示正常订单成本、取消/退货订单已填成本，后者单独列明金额。
- 明细展示商品图片、店铺、订单、商品、采购成本、售价和利润，可继续进入核算。

### 4. 数据罗盘，从全局看到店内商品

首页展示采购成本、预计销售额、预估利润、预估利润率及近7日均单量；更详细的分析放在数据罗盘中。

| 分析能力 | 可以查看什么 |
| --- | --- |
| 商品 / 店铺切换 | 查看商品表现，或比较各店铺经营表现 |
| 销量榜 | 商品按销售件数、店铺按有效订单数排名 |
| 利润榜 | 商品可切平均单件利润与累计利润，店铺按累计利润排名 |
| 亏损榜 | 找出累计净亏损的商品或店铺，继续核查具体订单 |
| 经营趋势 | 按订单量、销售额或利润查看周期变化 |
| 店铺与时间筛选 | 选择全部店铺或单店，按今日、近7天、近30天、自定义区间查看 |

支持完整的查看路径：**全局店铺榜 → 某店商品表现 → 商品详情 → 关联订单**。返回时保留筛选、榜单排序与滚动位置，方便连续比较。

### 5. 统计口径明确，适合日常核算

- **销售额与利润分清样本**：销售额包含尚未填写成本的有效订单；利润与利润率仅使用同一批完整核算的有效订单。
- **排除取消/退货对利润合计的干扰**：这类订单不计入预估利润合计，已填采购成本仍单列保留。
- **单件利润不被未核算销量稀释**：商品平均单件利润只除以已核算商品件数。
- **经营汇总不受列表条数限制**：订单列表最多展示最近500个包裹，罗盘聚合使用筛选范围内的全量订单。

### 6. 手机查看方便，也便于自己维护

前端适配手机与桌面浏览器，商品标题可切中文/原文，支持图片放大。缺图持续重试并复用已获取的缓存；标题翻译通过独立的本地模型服务完成。

项目采用Python、Flask与SQLite，前端为原生HTML/CSS/JavaScript，无需前端构建。推送与网页共用代码和数据，分别由服务运行；配置、业务数据与源码分开保存，便于备份和持续维护。

## 日常使用路径

1. 接入店铺API和Pushplus接收群组，由服务器持续采集店铺动态。
2. 微信收到新订单，打开利润页查看商品信息并填写采购成本。
3. 核对自动匹配的计费档位与费用，保存订单核算。
4. 在首页查看经营概况，进入罗盘比较店铺、商品及具体订单表现。

## 仓库与部署

- 唯一本地工作目录：`K:\github\ozon-shop-manager`。
- 当前服务器部署目录：`/opt/ozon-push-monitor`，沿用现有运行路径与两个systemd服务。
- 当前利润页：[订单利润](https://voice.xzbest.site/ozon-profit/)；[数据罗盘](https://voice.xzbest.site/ozon-profit/#compass)。
- 核心代码：`monitor.py`负责推送，`profit_core.py`负责核算，`profit_web.py`提供网页API，`compass_core.py`负责罗盘，页面资源位于`web/`。完整结构见项目说明。

真实配置、密钥、业务数据库和模型权重不在Git仓库中；样例配置及网页依赖分别见`*.example.json`和`requirements.txt`。原Docker/配置向导等早期入口仍保留供回溯，完整产品部署以当前部署文档为准。

此仓库以2026-11-01服务器最新版为初始版本，包含最新前端优化。推送、利润页与罗盘以后都在此维护，关键变更与回退信息持续记录到同一仓库。
