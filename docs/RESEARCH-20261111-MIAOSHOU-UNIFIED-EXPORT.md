# 妙手采购价/重量导入：跨状态统一导出调研

日期：2026-11-11。本轮仅回顾方案、查询公开官方帮助；未登录用户妙手子账号、未下载真实新导出文件，未改动线上功能或业务数据。

## 官方已确认

- 《历史订单与订单处理的区别》说明：历史订单可查询所有状态的订单，包含订单处理里的基本状态，另支持未付款、已完成；因此名称“历史”不等于仅已发货或已完成。
- 《导出订单流程》说明：“按当前查询导出”导出符合查询条件的所有结果，另有“按当前勾选导出”；导出明细可按订单、产品、包裹显示，并选自定义模板。
- 不能把订单处理单一TAB内的“全部查询结果”等同于跨所有TAB。优先验证“订单→历史订单”的统一查询导出路线。
- 公开资料尚不足以证明用户当前子账号的历史订单导出菜单、七列字段、自定义模板和包裹编号表现与订单处理完全相同，这些需用实际小样核对。

## 建议的小样流程

1. 从“订单”进入“历史订单”，选择Ozon和本方10家店。取消单一状态限制，确认查询包含所需未发货、交运及已发货状态。
2. 对选定时间范围执行查询，再找“导入/导出→按当前查询导出”。使用导出明细，沿用前次验证的包裹/商品行粒度与七字段模板；不要使用按商品合并的产品汇总。
3. 七字段仍为：店铺名称、订单编号、平台SKU、产品数量、采购金额(产品-RMB)、SKU ID、本地备注。无需为了跨状态增加正式必填列。
4. 从用户现有三个TAB各选一个已知完整订单号，检查一份导出是否全部包含，并核对订单编号是否仍对应Ozon完整posting号、采购金额是否为商品行总额、备注能否原样带出。
5. 同一订单拆成多个包裹时必须保留完整可定位编号，不能把父订单号或合并金额直接套给子包裹。不同显示粒度产生的新格式先经过原型匹配预览验证。

## 对每周维护方案的影响

- “跨状态一次导出”与“每次导出全部历史”是两件事；统一查询仍可限定店铺和时间窗口。
- 原方案“已发货＋最近14天发货时间”只能覆盖已发货，不适合直接套在跨状态查询上，否则未发货订单因没有发货时间而漏掉。
- 必须先核实历史订单实际可用的采购/修改/下单等时间筛选，再确定周更窗口。固定下单时间窗口会漏掉窗口外的晚采购/补称重/更正；没有修改时间筛选时不能声称绝不漏更。
- 导入端仍仅按店铺+完整订单+商品匹配、差异预览勾选后提交；空值不清空，相同数据跳过，无匹配/数量冲突标异常；备注重量是整包，不能再次乘数量。
- 双来源补重、正式持久化及线上接入仍未完成，不能把本调研描述为已上线能力。
