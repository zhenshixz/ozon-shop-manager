# 统一产品与代码结构

产品名：OZON 店铺助手。仓库名：`ozon-shop-manager`。

本地唯一工作目录为 `K:\github\ozon-shop-manager`。服务器现有项目目录为 `/opt/ozon-push-monitor`，这是同一产品在服务器上的部署位置，不是另一个独立项目。两个运行服务分工明确但共用代码和业务数据库，不需要硬合并成一个进程。

| 功能 | 主要文件 | 说明 |
| --- | --- | --- |
| 上新、出单微信推送 | monitor.py | OZON轮询、事件去重、批次和Pushplus发送 |
| 订单数据补全 | profit_sync.py | 同步利润页需要的商品、重量、图片等 |
| 采购成本与利润核算 | profit_core.py | 订单读取、输入校验、自动计费档位、利润计算 |
| 网页API | profit_web.py | Flask接口、页面和静态资源 |
| 数据罗盘 | compass_core.py | 店铺/商品维度、趋势、销量/利润/亏损榜 |
| 标题翻译 | profit_titles.py | 翻译队列与缓存，当前依赖本地模型服务 |
| 首页与弹窗 | web/index.html、web/app.js、web/style.css | 订单列表、核算、采购成本、首页统计 |
| 罗盘前端 | web/compass.js、web/compass.css | 商品/店铺榜单、店内商品表现与详情下钻 |
| 配置辅助、服务检查 | configure.py、cloud_service.py | 早期配置向导及现有云端检查；使用前阅读部署说明 |

## 核心口径

- 运营后台入口 `/ozonzusou/`；超重排查读取商品API单件重量，默认严格大于2000g。阈值可配置：手动检查立即使用最新值，自动检查从北京时间次日生效；独立后台提前15分钟检查，结果合入现有22:00上新汇总。归档只由用户勾选确认，逐款复查，结果数据库独立；旧利润/罗盘/促销入口继续可用。

- 拆包建议覆盖同款2～6件的全部整数组合，以及两款各1件。拆后各包独立选档、计平台费和货代费；推算/API估重须注明，不能将多件整包重量除成单件实称。
- FBS/rFBS状态独立任务默认30秒按变更时间批量核对、15分钟重叠，原300秒任务和6小时历史校准保留。页面前台每5秒只检查变化版本，有变化再读列表，统计仍按分钟刷新；编辑期间暂缓列表刷新，关闭后立即检查。API限流/异常可延迟，见状态提速维护记录。
- 运营起始日2026-10-24；按北京时间展示。
- 销售额含全部有效订单；利润及利润率只按同批完整核算的有效订单。采购成本另含已填写的取消/退货成本，并单独说明该金额。
- 自动选档以人民币包裹核算售价和有效包裹计费重量为准：售价≤135元且＜500g为超轻小件，500g起至25kg为低客单；售价＞135元且≤2000g为轻小件，超过2000g至25kg为大件。轻小件默认17%；其他费用系数见profit_core.py。
- 拆发逐包核算售价、重量、运费、平台费和货代费，再汇总整单利润；拆合包建议同样比较这些费用的合计。采购价为单件价，其他成本按本单收取一次。手填费率保留明确覆盖，自动费率不能写死为合包档位。
- 人工整包重量只适用于确认时的商品/件数组合；组成变化必须重新确认或由完全匹配的已保存拆发方案接管。不能把两件整包重量当成单件实称继续沿用。新增计算分支应包含用户表格的独立预期值，并核对保存、列表与罗盘一致。
- 同店、同货号单件包裹跟随最新人工实称。未核算的多件包裹默认按单件实称乘数量，并随单件更正；多件整包已手动核算则保留本单。推算注明来源，不当作人工实称。明确恢复 API、组成变化待核实、已保存未交接拆包方案仍按各自规则处理。
- 商品利润榜区分平均单件/累计，单件分母只用已核算件数；店铺利润按累计。罗盘支持全局店铺→店内商品→关联订单。
- 实际采集和推送周期读取服务器config.json，不能把早期指南里的默认值当作线上实时配置。

## 运行数据与外部依赖

- 两个主要服务共用 `data/monitor.sqlite3`。数据库包括真实订单、采购价、缓存和通知状态，不放入Git。
- 运行配置为config.json、profit-web.json、title-translation.json，均只在部署环境维护；仓库提供脱敏样例。
- 私钥在本机仓库外的 `.server-access`，不复制进产品目录。
- 本地标题模型服务位于服务器 `/opt/ozon-title-engine`，由ozon-title-engine.service提供127.0.0.1:5311接口；模型引擎及权重属于运行依赖，不打包进入本源码仓库。恢复方式见本地翻译维护文档。
- 当前生产是systemd部署。根目录Dockerfile/compose.yaml和部分启动脚本来自早期推送版，不是当前完整产品的一键部署方案。
