# 2026-11-08 妙手采购成本接入调研（未开发）

## 结论

妙手存在官方开放平台，支持 Ozon、订单/包裹、采购、仓储等模块。官方接入页要求使用主账号登录创建应用，按接口申请权限。因此现有子账号不能仅凭网页登录状态或 OZON API Key 接入妙手 OpenAPI，需要代运营主账号配合申请独立应用。

但“有采购接口”不等于“能取到每笔 Ozon 代发采购实际成本”。公开文档能确认仓库采购单包含价格字段；公开包裹列表/详情示例未见采购成本或代发采购记录关联字段。代发采购能否通过已开放接口完整取出，需要主账号后台当前文档、妙手客服或一笔已采购订单的只读返回来证实。尚未取得凭据或实调业务 API，不能宣布全自动方案已验证可用。

已明确存在的低成本备用路径是“订单 → 采购记录 → 导出采购单”，另可查看“数据 → 利润明细 → Ozon → 订单&产品 → 导出数据”。可先用导出样本评估批量导入，从逐单填写改为批次处理。

本轮只改本地研究文档；未修改线上代码、服务器配置或业务数据，未创建应用、采购或发送消息。

## 用户采购流程补充

用户已确认：直接在购物平台下单，再把采购信息录入妙手。这是“外部采购后录入采购信息”的场景，不能直接认定为通过妙手代发采购创建的记录。[官方流程说明](https://erp.91miaoshou.com/help_center/article_8346.html)明确描述此方式可同步快递单号，但该描述不足以证明采购实付金额也被同步。

用户进一步提供截图，确认外部采购录入后，订单列表已经显示采购金额（示例为 CNY 24.75）。因此“妙手里是否有金额”已得到肯定证据；金额是否为单件/整笔采购实付、是否含国内运费与优惠、是否跨多个销售订单仍未核对。下一步应检查导出文件和 API 能否完整读出这一金额及销售商品关联，不能仅凭后台有金额认定公开接口一定有字段。

## 导出与 API 的数据风险和落地比较

- 按建议的只读取数设计，我们服务器向妙手请求数据，不把自用工具里的重量、手工核算或数据库推回主账号。接入无需向代运营额外提供本工具的服务器权限或 OZON Key。主账号在妙手内部原有的可见范围仍由其账号权限决定。
- API 新增的是持续有效的访问凭据。凭据泄漏后可能读取获准接口中的数据，“只读”不等于不会泄露；应创建专用查询应用，密钥只放后端，并向妙手确认应用级店铺范围。未证实按店铺隔离时，不能把客户端 `shopId` 筛选当成授权隔离。
- 导出可以先限定本方店铺与必要列，无需保存 ERP 应用密钥；代价是定期导出和上传。文件仍有泄露风险，不纳入 Git，不需要导入收件人电话地址等无关字段。
- 当前利润页按用户要求免登录，知道网址即可访问已展示的成本/利润。这是现有访问方式的风险，与选择 API 或导入无关；本轮没有更改访问限制。

推荐顺序：先检查“利润明细 → Ozon → 订单&产品”能否导出所需列，或核对“订单 → 采购记录”导出是否包含外部录入记录。当前还没有拿到该账号的导出文件，不能保证模板字段一定够用。文件至少需要店铺、销售订单/包裹号、商品货号/SKU、数量和采购金额；无法精确关联的行应留待确认。

导入应做成现有工具的可重复使用入口，而非每次由 AI 手工改库：导出 → 上传 → 查看匹配/变更/冲突 → 确认更新。默认填补空成本或替换历史沿用值，人工确认成本的冲突单列，重复上传不重复累加费用。

特别注意：[Ozon 利润明细官方说明](https://erp.91miaoshou.com/help_center/article_9412.html)指出，拆分包裹的部分金额只计在主包裹。导入时不能把同一总采购金额重复计入所有包裹，也不能将子包裹空金额当成零成本。两条方案都必须先对齐金额口径，自动 API 并不天然比导出更准确。

综合评估：导入当前前置条件少、费用范围可控，适合先减少逐单录入；API 日常自动化更好，但需主账号、开放字段和授权范围确认。上述半天至一天/一至两个工作日估算只在取得可靠模板或可用字段后成立，不包含审核等待。未开发导入或 API 接入。

## 已核实的官方资料

1. [妙手开放平台](https://erp.91miaoshou.com/open_platform.html)：接入流程第一步为主账号登录；创建应用，获取 AppKey/AppSecret，申请接口权限。无须额外开发者资质认证。
2. [开放平台功能说明](https://erp.91miaoshou.com/help_center/article_14560.html)：2026-07-14 更新；入口为“更多 → 系统管理 → 开放平台”；按全部/指定接口申请，审核后查看凭证。指定接口权限不等于按店铺隔离，未查到明确的应用级店铺限制说明。
3. [快速接入文档](https://qrzmpphmpd.apifox.cn/9239541m0)：基础域名 `https://openapi-erp.91miaoshou.com`；HMAC-SHA256 签名，五分钟时间偏差范围；存在账户/应用/接口维度秒、分、日限流。IP 白名单为账户级，同一主账号的所有应用共用，不能未经确认直接修改而影响其他接入。
4. [采购单功能与代发采购功能对比](https://erp.91miaoshou.com/help_center/article_3198.html)：仓库采购单用于补货入库，订单代发采购独立于仓库系统，两者是不同业务流程。
5. [采购记录与订单的关联](https://erp.91miaoshou.com/help_center/article_2218.html)：记录代发采购、1688 批量采购的采购金额、时间、采购账号，支持订单关联及按平台/店铺筛选、导出采购详情。
6. [利润明细说明](https://erp.91miaoshou.com/help_center/article_2171.html)：采购金额可能来自代发采购、提交代打包金额或仓库商品成本；无对应数据时仍为空。此数据存在于后台，不代表已开放为 API。
7. [Ozon 利润明细](https://erp.91miaoshou.com/help_center/article_9412.html)：支持订单&产品、订单、包裹、店铺维度。导入需优先使用商品行粒度，不可将整单采购总金额当成每件采购价。
8. [子账号设置](https://erp.91miaoshou.com/help_center/article_3114.html)：主账号配置角色的查看、导入导出等功能及负责店铺。导出可否由子账号完成，以当前已授予权限为准。

公开页面/API 文档均于 2026-11-08 查阅；页面内容可能继续更新。只采用官方帮助、官方站点及其品牌开放平台文档，不采用第三方文章的收费或成功率说法。

## 主账号需要配合的具体事项

- 在已管理这 10 家店的主账号下，申请专用应用，只申请需要的查询权限；应用 ID 和 Secret 由服务器配置保管，无需提供主账号密码。
- 确认 Ozon 代发采购记录、实付/优惠/运费是否可读，销售订单与采购商品如何关联，淘宝/拼多多/1688 是否覆盖；只开放仓库采购单时不满足一件代发成本需求。
- 确认能否在应用授权层限制到本方 10 家店。若主账号还有其他客户，不应把“程序自行筛选”当成凭据权限隔离；可考虑代运营侧按本方店铺过滤后提供数据，或按店铺导出。
- 确认 API 是否额外收费、各接口配额、有效期与审核周期。公开页面未提供可据以承诺长期免费的采购 API 价格表；ERP 店铺免费额度不能替代 API 收费依据。
- 若先导入，只需现有子账号具备本方店铺采购记录/数据查看及导出权限；已有权限时不需要每次请主账号操作。

## 适合现有工具的实现方式（待批准开发）

匹配使用店铺映射 + Ozon 订单/包裹号 + 商品货号/SKU；按商品行和数量归一为单件采购成本。多件、混款、拆单必须核对归属，只有整单金额时不得随意平均到不同商品。国内运费、优惠、退款的口径确认后再入账，不能与现有运费/货代重复扣。

优先级建议为：人工本单确认 > 该单已验证的实际采购记录 > 同商品历史参考 > 待填。缺失/未采购不填零，自动值注明妙手来源与同步时间，重复同步幂等。先只读验证单店 5–10 笔含单件、多件、混款/拆单、优惠/运费场景的样本，再接入利润和罗盘。

对接成本预估（工程判断，不含主账号操作、审核等待或厂商补接口）：

| 路径 | 前提 | 工作量估计 | 判断 |
| --- | --- | --- | --- |
| 只读字段验证 | 专用凭据已审核、文档和样本齐全 | 约 0.5–1 小时 | 先确认能否拿到真正的成本及关联关系。 |
