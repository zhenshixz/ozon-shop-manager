# 采购价与实称导入：本地模拟

独立页面，使用真实订单的只读 JSON 副本。确认、撤销仅操作进程内存；本程序没有数据库连接、生产写接口和同款自动沿用调用。重启恢复快照。

## 启动

需要本地 Python 3.9+，无第三方依赖：

```powershell
python -B prototypes/purchase-import/server.py --data-dir K:/github/diagnostics/purchase-import-20261108 --port 8768
```

打开 http://127.0.0.1:8768/ 。当前已启动本地服务，可直接打开。

`--data-dir` 必须位于 Git 仓库外，包含 `snapshot.json`（orders 数组）、只读复制的 `profit_core.py` 和 `parcel_comparison.py`。真实数据、用户 Excel、截图不放入仓库。服务只绑定回环地址，不对局域网开放。

## 使用

1. 选择妙手导出的 `.xlsx`，七列：店铺名称、订单编号、平台SKU、产品数量、采购金额(产品-RMB)、SKU ID、本地备注。
2. 逐行按店铺名称＋完整订单号＋平台SKU匹配。平台SKU为空才回退 SKU ID；两者均有值时必须一致，件数必须一致。无法唯一匹配或重复记录不更新。
3. 采购金额为商品行合计，除件数存单价，最多8位小数且必须精确整除；保留 ¥31.07/2=¥15.535 的精度。空金额跳过，0元采购暂需人工处理。
4. 备注只接受独立的 `312g` / `312克` 等正数，代表真实整包重量，不乘件数。已有同值实称跳过；只有 API 同值则仍可确认实称来源。
5. 有效差异默认全选，各字段可独立取消，筛选不改变勾选。已人工核算的值被替换时提示；利润随勾选预览。确认前不写入模拟订单。
6. 确认后查看订单成本、重量、利润；可撤销上次模拟。再次导入相同文件自动跳过相同值。预览过期必须重新上传。

## 首版边界

- 数据仅包含抽取的9笔订单，不代表完整店铺；其他订单无法匹配是预期结果。
- 多种商品订单：采购成本仍按商品行匹配，整包重量暂跳过并说明，避免多行重复或冲突。正式接入前需补充这种样例确认订单级重量交互。
- 已保存拆包方案：整包总重不能替代各包实称，重量暂跳过，采购成本可更新。
- 本地模拟的撤销按最后一个批次恢复内存；真实版本必须增加字段级审计及并发校验，不能直接复用内存撤销作为生产恢复。
- XLSX 使用标准库 ZIP/XML 只读解析，暂不支持公式、多个工作表、超过2000行、超过5MB文件或25kg重量。
- 不联动同货号其他订单。正式版本需要单独评估既有重量/采购价沿用函数的范围，不能直接调用原保存流程扩大影响。
